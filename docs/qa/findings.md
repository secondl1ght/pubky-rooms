## Bugs
- Tag chips vanished when two adds were in flight (2026-09-28; e.g. a 400 ms round trip and Enter twice within 150 ms): a hook's `pushEvent` locks the hook element until its reply, a second push renews the lock, so LiveView patched a clone of the locked container for the first reply, and the second reply's `data-phx-skip` placeholders for the unchanged chips found no node to keep (empty spans). The hidden field still carried every label, so rooms were created correctly. Fix: the `TagInput` hook sits on the "+"/field control, so the chips and the hidden field are patched outside any lock. The same risk applies to any hook whose element contains server-rendered function components that change while its pushes are in flight (Composer: `typing`; ScrollToBottom: `load_older`) — check during the regression pass. The hooks had no tests at all (an omission from the plan, not a decision): vitest + jsdom now cover all five (`assets/test/hooks`), including the read-only limit state and the "hook element holds no chips" guard; the LiveView lock race itself still needs a real client. — fixed
- Hard refresh of a room page flashed placeholders ("Room" title, 0 members, no settings gear, a Join button for a member) before the real values: the disconnected first render used the mount defaults and only the connected mount asked the room server. The first render now takes the running room server's snapshot when the room is warm (any refresh: messages, anonymous count and the tag "+" included, nothing left to flash), paints a cold room from what the Directory knows (definition, members, tags, who is online, the viewer's own membership) with "Loading messages…" in the list, and a room this node has never seen gets one page-level loading state instead of placeholders (`scripts/headless_room.exs` makes one). Mute lists are cached or loaded (1 s cap) before any message is painted, and on a timeout the messages wait for the socket, so a muted author never shows and then vanishes. Left for later (2026-09-28): in that timeout fallback the muted member's marker and Unmute label still arrive with the socket (no control can fire before then and a repeated mute is idempotent, so it is cosmetic). See Polish. Gotcha: whatever a LiveView needs for a flash-free first paint must be readable without the socket (ETS here), and `connected?/1` branches must fill it in. Dead-render test with `get/2`. — fixed
- The tag limit message flashed and disappeared: the hook disabled the focused input, disabling blurs, and the blur handler folded the field. The field is now read-only at the limit and stays open with the red placeholder until it is left; Backspace still removes the last chip. — fixed
- Room page tab title seemed stuck on "Room · Pubky Rooms" in Claude's browser tabs while the room name rendered. LiveView applies `page_title` inside `requestAnimationFrame`, which never fires in a hidden tab (both automation tabs report `visibilityState: hidden`); the server diff carries the title (traced) and visible tabs update. Also, `Phoenix.LiveViewTest.page_title/1` ignores the title in the join payload, so tests must assert it after a later change. — not a bug

## Polish (found by Claude, signed-in pass)
- `/me` shows "No profile found yet" when the real problem is that the user's own key does not resolve (PKARR record gone; testnet relays lose them on recreation). Writes still succeed via the session, so a saved nickname never appears. Not distinguishable today: `Pubky.Storage.get` returns the resolver's `:not_found` unchanged, the same atom as a missing file, so the profile fetcher reads both as "no profile" (the stream layer sees the resolver error directly, hence rooms can flag it). Fix: wrap resolution failures in the library (`{:error, {:resolve, reason}}`), map to a distinct profile source in the cache, show "Your key does not resolve right now" on `/me`. ~1 h with tests. Low priority: on mainnet Ring republishes records. — open
