# Pubky Rooms — sovereign live chat on Pubky, built with Phoenix

## Context

Part of the Pubky "Vibes" initiative: build and showcase a novel app on the Pubky stack using Phoenix/Elixir, exploiting what each does uniquely well. Pubky gives durable, user-owned, per-user data (files on the user's own homeserver, key-based identity, per-user SSE change streams). Phoenix gives cheap concurrency (one supervised process per homeserver subscription), PubSub fan-out, LiveView, and Presence, which is the ephemeral "who is here now" layer Pubky has no concept of.

**Quality bar (user's requirement):** this is not a hack project. Vibes projects are meant to become stable, production products. Pubky Rooms will be hosted at **rooms.pubky.app** and must feel like the same product as Pubky App (same design system), and it will be integrated into Pubky App (Rooms entry in navigation, discovery via Nexus). The user is new to Phoenix/Elixir and to this depth of the Pubky stack, so the implementation must be self-explanatory: clear module docs, a README that teaches the architecture, conventional Phoenix structure, and tests that double as documentation.

**Decisions made with the user:**
- App: **Pubky Rooms**. Chat rooms where every message is a file the author writes to their own homeserver. Our server stores nothing durable: it subscribes to members' homeserver event streams, fans out to LiveViews, and adds presence/typing/live updates. Anyone can run a competing frontend over the same data (credible exit by construction). UX signature: a sent message flips from "pending" to a "stored on your homeserver" check mark when its own SSE event arrives.
- Client: **pure Elixir** Pubky client library (`pubky_ex`, OTP app `:pubky`), extractable to hex later. No Elixir/Erlang Pubky or PKARR library exists anywhere, so this is an ecosystem contribution in its own right. No Rust/NIFs.
- Auth: **grant auth only** (v0.10+; user confirmed Pubky Ring v1.19 approves `signin_grant`). No cookie flow.
- Dev env: **local testnet via pubky-docker** + Pubky Ring Simulator; mainnet is a config switch. Deploy target: **Fly.io**.

**Remotes and release path (user's decision):** all code lives under the user's own GitHub account (`secondl1ght`) for now: this repo (`pubky-rooms`) and a **fork** of `pubky/pubky-app` for the integration work. Migration to the `pubky` org, the `rooms.pubky.app` domain, and the upstream Pubky App PR happen **later**, only after the project has been live in our own deployment for users to try and has been accepted into the production ecosystem. Until then the app runs at a Fly-hosted URL and the Pubky App integration is exercised on the user's deployed fork.

**Repo layout** (`/home/mk/CODE/pubky-phoenix`; one git repo, remote `github.com/secondl1ght/pubky-rooms`):

**On-homeserver data model** (namespace `/pub/pubky-rooms/`, capability `/pub/pubky-rooms/:rw`). Room ref = `{creator_z32, room_id}`, URL `/r/<creator>/<room_id>`. IDs: 13-char Crockford base32 of microsecond timestamp (monotonic per node via `:atomics`), lexical = chronological. All JSON has `"v":1`; reader caps bodies at 16 KiB; author is always taken from the path/event owner, never the body.
```
rooms/<room_id>                         {v,name(1..64),topic(≤280|null),visibility:"public"|"unlisted",created_at}
members/<creator>/<room_id>             {v,joined_at,room:"pubky://<creator>/pub/pubky-rooms/rooms/<room_id>"}   DELETE = leave
messages/<creator>/<room_id>/<msg_id>   {v,kind:"text",content(1..2000),reply_to(uri|null, same room),created_at,edited_at|null}  PUT overwrite = edit, DELETE = delete
reactions/<creator>/<room_id>/<author>/<msg_id>/<key>   {v,created_at}   key ^[a-z0-9_]{1,16}$ ; DELETE = un-react
bans/<room_id>/<banned_z32>             {v,created_at,reason(≤140)}       honored only from the creator's homeserver
profile.json                            {v,name(1..32)}  optional local nickname (later)
```
`PubkyRooms.Rooms.Paths.parse/1` → `{:room,id} | {:member,c,id} | {:message,c,id,msg_id} | {:reaction,…} | {:ban,id,z32} | :profile | :ignore` with strict segment regexes.

**Supervision tree:** Telemetry, PubSub, `Pubky` app, `RateLimit` (ETS fixed window), `Events.Cursors` (ETS z32→last cursor), `Auth.SessionStore` (memory only — ADR 0005: the encrypted cookie carries sid + credential; ETS caches hydrated `%Pubky.Session{}` while LiveViews are attached, dropped 60 s after the last disconnect; refreshed tokens written back), `Profiles.Cache`, `Task.Supervisor`, `Events.StreamSupervisor` (DynamicSupervisor of `Pubky.Events.Stream`), `Events.Subscriptions` (refcounted per-user subscriptions grouped by homeserver, shard at 50, `acquire/2`/`release/2`, owner monitoring, cursor capture via `reverse=true&limit=1` before listing history), `Rooms.Directory` (ETS+DETS: rooms, members, user→rooms), `Rooms.Registry` + `Rooms.RoomSupervisor` (DynamicSupervisor of `RoomServer`), `Presence`, `Endpoint`.

**Events topology:** `Pubky.Events.Stream` → `PubkyRooms.Events.dispatch/1` (advance cursor if greater, dedupe replays) → PubSub `pubky:user:<z32>` and `pubky:all`. `RoomServer` subscribes to `pubky:user:<member>` for its members and ignores paths not for its ref. `Directory` subscribes to `pubky:all` for `{:room,_}`/`{:member,_,_}` only. Path filter on every stream `/pub/pubky-rooms/`.

**RoomServer** (GenServer per active room, ETS `ordered_set` keyed `{msg_id, author}`): `ensure/1`, `attach/2`, `history/2`, `older/3`, `members/1`, `register_pending/3`, `cancel_pending/2`. Bootstrap: GET creator's RoomDef (404 → `:not_found`), bans, `Subscriptions.acquire(members)` **first** (captures cursors), then per member reverse-list last 50 messages + GET each (skip banned), status `:ready`, broadcast. Events: message PUT with pending hash match → `:confirmed` without a GET, else GET+validate+upsert; DEL → remove; reactions update a map on the target; bans (creator only) hide/unhide authors; room PUT/DEL → updated/closed. Pending sweep every 5 s: >15 s → verify by GET (exists → confirm, 404 → `{:message_failed, key, :vanished}`). Idle: 10 min after last viewer → release subscriptions, stop.

**Send path:** `send` event → rate limit (5 per 5 s) → build `%Message{}` with `Ids.next()` → encode → `hash = Blake3` → `RoomServer.register_pending` (before the PUT, so the SSE event can never beat registration) → `stream_insert` pending → `start_async` `Pubky.Storage.put(session, path, bytes, content_type: "application/json")` via `PubkyRooms.Pubky` facade (behaviour; `Live` impl, `Fake` in tests). Failures map to `:failed` with reason (quota 507, rate-limited 429 + Retry-After, unauthorized → session expired, unreachable) with Retry/Discard. Same pattern for edit/delete/react/join/leave/ban/create room.

**Auth in Phoenix:** `AuthLive` (`/login?return_to=`) renders QR (`EQRCode.encode(url) |> EQRCode.svg`), copy-link, `<a href={url}>Open in Pubky Ring</a>`, testnet hint linking to `simulator.pubkyring.app`; `start_async(:await, fn -> Pubky.Auth.GrantFlow.await(flow, 120_000) end)`; on success `SessionStore.put(session)` → sid → `Phoenix.Token` handoff → `GET /auth/complete` (verify ≤60 s, single-use) writes sid, public key and the exported credential into the encrypted httpOnly cookie (ADR 0005) → redirect. `UserAuth` plug + `on_mount :mount_current_user` (assigns `current_user %{pubky, name, avatar_url}`, acquires own event subscription, tracks lobby presence, throttled `Directory.sync_user`) and `:require_authenticated`. Logout: `DELETE /auth/grant/session` best-effort, drop session. Cookie holds sid + credential, encrypted and signed, 30 days, `Secure` in prod; caps requested `/pub/pubky-rooms/:rw`.

**Router:** `live "/"` LobbyLive (:index, :new), `live "/r/:creator/:room_id"` RoomLive, `live "/login"` AuthLive, `get "/auth/complete"`, `delete "/logout"`, `live "/me"` MeLive (identity, sign out). *(M4 done; see `docs/notes/rooms-app-design.md` → Implementation notes for deviations.)*

- **Room tags + Nexus discovery (mainnet).** Nexus v0.4.1 indexes *universal tags*: any app may write a `PubkyAppTag` (`{uri, label, created_at}`, id = Crockford base32 of the first 16 bytes of blake3(`"{uri}:{label}"`), label trimmed+lowercased ≤20 chars) at `/pub/<app>/tags/<id>`, and Nexus indexes the tagged URI as a Resource under that app namespace (`ExtendedParsedUri::UniversalTag`). Users can also add tags to a room from inside Pubky Rooms (writes to our tags dir). Nexus base URL is config (`nexus_url`, nil on testnet unless the pubky-docker `backend` profile with nexusd is running, in which case `http://localhost:8080`). Note: Nexus only indexes homeservers it watches; rooms created by users on unwatched homeservers still work but only appear in the local Directory.

## Production-quality checklist (applies to every milestone)

- Correctness: every homeserver write validated client-side with the same limits the reader enforces; idempotent event handling; no unbounded ETS growth (idle-room shutdown, TTL caches, bounded pending maps).
- Resilience: supervised streams with backoff + jitter; per-homeserver failure isolation; graceful degradation when Nexus or a member's homeserver is down (room still works from reachable members); startup re-bootstrap verified by tests.
- Security (ADR 0005): credentials live only in the encrypted, signed, httpOnly cookie and in server memory while the user is connected — nothing on disk; single-use signed handoff token; strict path/segment validation on everything read from homeservers; content rendered as text (no HTML), links auto-linked safely; rate limits per session and per IP; CORS restricted; security headers via `plug :put_secure_browser_headers` + CSP for our own assets.
- Observability (ADR 0006: aggregate only, no identifiers, nothing exported, no client-side analytics): Telemetry events for stream connects/disconnects, event lag (cursor age), bootstrap durations, send→confirm latency; structured logs; `/healthz` for Fly checks; optional PromEx later.
- Accessibility: keyboard-navigable composer and lists, ARIA live region for new messages, focus management, color contrast per the design tokens.
- Tests: unit + LiveView + testnet integration as listed; `mix format --check-formatted`, `mix credo --strict`, `mix dialyzer` in CI (GitHub Actions running unit tests on every push; testnet job optional).
- Docs: README (architecture diagram, data model, credible-exit story, run locally, deploy), moduledocs, ADR-style notes for the key decisions (server-side grant, no database, universal tags).

## Appendix — verified Pubky facts (Sept 2026)

- Identity Ed25519; pubky = 52-char z-base32. PKARR user record `_pubky HTTPS 0 <hs z32>`; homeserver record advertises PubkyTLS direct (`HTTPS 1 . port=6287`) + ICANN (`HTTPS 10 domain [port]`) + `A`. Relay GET `https://pkarr.pubky.org/<z32>` (120/min) or `https://pkarr.pubky.app` (10/min); testnet `http://localhost:15411`.
- Homeserver routes (v0.11.0): storage `/storage/{z32}/pub/...` (or legacy path + `pubky-host`), dir listing GET on `…/` with `limit/cursor/reverse/shallow`, `GET /info`, `GET /events-stream?user=&path=&live=&limit=&reverse=`, `GET /events/?cursor=&limit=`, `POST /auth/grant/session`, `POST /auth/grant/signup`, `GET|DELETE /auth/grant/session`, `GET /auth/grant/sessions`, `DELETE /auth/grant/session/{gid}`. Deprecated cookie routes `/signup`, `/session` (not used).
- Grant flow: app generates 32-byte secret + PoP keypair; QR `pubkyauth://signin_grant?caps&relay&secret&cid&cpk`; relay inbox id = b64url(blake3(secret)); Ring posts `nonce(24)||XSalsa20-Poly1305(grant JWS)`; app decrypts, decodes claims `{iss, client_id, caps, cnf, jti, iat, exp}`, resolves `iss` homeserver, signs PoP `{aud: hs, gid: jti, nonce, iat}` with the PoP key, POSTs `{grant, pop}` → `{token (1 h), session{...}}`; `Authorization: Bearer`. Durable credential = grant JWS + client secret + hs; refresh = re-POST with fresh PoP.
- SSE frames: `event: PUT|DEL`, `data: pubky://<z32>/pub/...`, `data: cursor: N`, `data: content_hash: <std b64 blake3>`; keep-alive comment every 15 s; ≤50 users per stream, one stream per homeserver; resume cursor exclusive; no-path default = `/pub/` only.
- pubky-app-specs v0.7: `/pub/pubky.app/profile.json` `{name,bio,image,links,status}`; posts/tags/bookmarks/follows/files/blobs; Timestamp IDs 13-char Crockford base32 (µs); Hash IDs = first half of blake3 in Crockford base32. Nexus REST `https://nexus.pubky.app/v0/…` (swagger at `/swagger-ui/`).
